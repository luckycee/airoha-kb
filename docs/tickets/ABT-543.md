### 2025/05/12 11:29 — [人名44]

Hi @[邮箱已隐藏] 

这题是PC或者网易播放器的IOT问题，按经验一般会有如下问题：
 # 只有在连线的时候通知一次播放状态为STOP <这台有>
 # 在暂停/播放的时候没有AVRCP状态的更新<这台有>
 # 暂停后20s到30s才会停止数据流
 # 发送PAUSE可以开始播放，发送PLAY可以暂停<这台有>

分析 SDK_5.2.0按播放暂停正常.rar：17-22-18开始点击暂停-播放-暂停-播放，按键功能都正常。

#4621连线后通知了STOP，但是按描述实际情况是播放的<IOT CASE #1>

#15820 按描述是发送的暂停，但耳机是发的播放，而PC实际情况是响应了暂停 <IOT CASE #4>, 在此之后PC也没有通知播放状态更新到了暂停<IOT CASE #2>

#16549 按描述是发送的播放，但耳机是发的暂停，而PC实际情况是响应了播放 <IOT CASE #4>, 在此之后PC也没有通知播放状态更新到了播放<IOT CASE #2>

[图片: image-2025-05-12-11-23-25-636.png]

这里的原因是SDK 5.2.0 会根据耳机第一次发的按键动作来判断第二次应该发什么按键，并不去管这中间是否有在PC上操作，这样看起来是有问题的，假设如下步骤：
 # 音乐处在暂停状态，耳机上控制播放
 # PC上控制暂停
 # 耳机上再操作===>{color:#de350b}*耳机会因为#1发了播放而发暂停给PC，明显是不正确的*{color}

 

SDK 5.4.0会在#2发生的时候，主动去查询一下播放状态，但是遗憾的是主动查的状态也是错误的：

[图片: image-2025-05-12-11-27-38-065.png]

综上所述，这个问题是PC的已知IOT问题，建议不做修改，请评估。
